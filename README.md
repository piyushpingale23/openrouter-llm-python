# OpenRouter LLM with Python

A beginner-friendly Python project demonstrating how to interact with Large Language Models (LLMs), request structured AI responses, and integrate external APIs using Python libraries.

This project currently includes three examples:

1. **OpenRouter Client** — send a prompt to an LLM using the OpenAI Python SDK.
2. **Structured Output with Pydantic** — generate structured JSON responses and validate them using Pydantic.
3. **Weather API Tool** — retrieve current weather information using the OpenWeather API and the Requests library.

## 2. Technologies and Libraries

### Python

The programming language used to build the application and integrate with external APIs.

### OpenAI Python SDK

The `openai` package provides a client for making requests to LLM APIs that follow the OpenAI API format.

In this project, the SDK communicates with OpenRouter.

### OpenRouter

[OpenRouter](https://openrouter.ai/) provides a unified API for accessing supported LLMs through a common endpoint.

The application uses OpenRouter to send prompts to the selected model and receive generated responses.

### Pydantic

The `pydantic` package defines data models and validates data types, field constraints, and structured responses.

In this project, it validates the JSON response generated by the LLM.

### Requests

The `requests` package sends HTTP requests to external APIs.

In this project, it calls the OpenWeather API to retrieve weather information.

### Python Standard Library

The project also uses built-in Python modules:

- `os` — reads environment variables.
- `json` — works with JSON data.
- `typing` — provides type annotations, including `Literal`.
- `getpass` — securely prompts for an API key without displaying it while typing.

## 8. Configure API Keys

This project uses two external services, so their API keys are configured separately.

### OpenRouter API Key

Create an API key through [OpenRouter](https://openrouter.ai/).

Set the environment variable in your terminal:

```bash
export OPENROUTER_API_KEY="your_openrouter_api_key"
```

Both `1_openrouter_client.py` and `2_structured_output.py` use this key.

The basic client script prompts for the key if the environment variable is not set. The structured-output script expects the environment variable to be available.

### OpenWeather API Key

Create an API key through [OpenWeather](https://openweathermap.org/api).

Set the environment variable:

```bash
export OPENWEATHER_API_KEY="your_openweather_api_key"
```

The weather example reads this variable when initializing `WeatherTool`.

Replace the placeholder values with your actual API keys.

**Security:** Never hardcode API keys in your source files or commit real keys to GitHub. If a key is exposed, revoke it and generate a replacement.

These `export` commands apply to the current shell session and its child processes.

## 9. Run the Examples

Ensure that your virtual environment is activated and the required API keys are configured.

### Example 1: Basic LLM Request

Run:

```bash
python src/1_openrouter_client.py
```

The application sends the following prompt:

```text
What is Java?
```

It uses the configured model:

```python
MODEL_NAME = "openai/gpt-4o-mini"
```

The response is generated by the selected LLM and printed in the terminal.

The script also configures:

- `temperature` — controls the randomness of the generated response.
- `top_p` — controls token selection using nucleus sampling.
- `max_tokens` — limits the number of generated tokens.

The generated response may vary between requests.

### Example 2: Structured Output with Pydantic

Run:

```bash
python src/2_structured_output.py
```

This example defines a `ConceptExplanation` model with fields such as:

- `topic`
- `summary`
- `difficulty`
- `key_points`
- `example`
- `confidence`

The application generates a JSON Schema from the Pydantic model and sends the schema with the prompt to OpenRouter.

After receiving the response, it uses:

```
ConceptExplanation.model_validate_json(structured_text)
```

to parse the JSON and validate it against the defined model.

If validation succeeds, the application prints the validated response as JSON.

**Important:** Structural validation does not guarantee that the LLM's explanation is factually correct.

### Example 3: Weather API Tool

Run:

```bash
python src/3_weather_tool.py
```

The application requests current weather information for Pune:

```
weather = weather_tool.get_current_weather("Pune")
```

The response includes:

- Location
- Temperature in Celsius
- Humidity
- Wind speed
- Weather condition

The application uses the Requests library to send an HTTP GET request to the OpenWeather API.

## 10. Configuration and API Endpoints

| Setting               | Purpose                                                       |
|-----------------------|---------------------------------------------------------------|
| `OPENROUTER_API_KEY`  | Authenticates requests to OpenRouter.                         |
| `OPENWEATHER_API_KEY` | Authenticates requests to OpenWeather.                        |
| `MODEL_NAME`          | Identifies the LLM selected for the request.                  |
| `base_url`            | Specifies the OpenRouter API endpoint used by the OpenAI SDK. |
| `temperature`         | Controls response variability.                                |
| `top_p`               | Configures nucleus sampling.                                  |
| `max_tokens`          | Limits the generated response length.                         |

OpenRouter endpoint:

```text
https://openrouter.ai/api/v1
```

OpenWeather current weather endpoint:

```text
https://api.openweathermap.org/data/2.5/weather
```

Model availability, API requirements, and pricing can change. Consult the relevant provider's documentation for current details.
